## 1. Goal & Success Criteria

### Goal
Implement the data pipeline (`build-municipalities.ts`), the metrics calculation engine (`src/lib/metrics.ts`) with comprehensive unit tests (`tests/metrics.test.ts`), seed `data/sites.yaml` from Section 12 of PLAN.md, and verify with `pnpm build:data` and `pnpm validate`.

### Success Criteria
1. `data/municipalities.csv` contains all 1,741 municipal assemblies (792 cities, 743 towns, 183 villages, 23 special wards) plus 47 prefectures, with official 5-digit/6-digit codes and population figures. Designated-city administrative wards are appropriately handled/mapped to parent cities.
2. `src/lib/metrics.ts` implements:
   - Municipal coverage (count): covered municipal assemblies ÷ total municipal assemblies (national denominator 1,741).
   - Population coverage: sum of population in covered municipalities ÷ total population (default ranking sort).
   - Prefectural assembly coverage: yes/no badge per prefecture (not mixed into rates).
   - Tie-breaking: sorted by population coverage desc, then municipal coverage desc, then prefecture code asc.
   - Status rules: `active` and `stale` count as covered; `dead` and `building` do not count.
   - Duplicate rule: Multiple sites covering the same assembly count exactly once toward coverage.
3. `tests/metrics.test.ts` achieves 100% coverage on metrics logic, including:
   - Zero coverage prefecture
   - Multiple sites for one municipality
   - Prefectural assembly site
   - Dead and building sites excluded
   - Correct ranking and tie-breaking
4. `data/sites.yaml` seeded with verified entries from Section 12 of PLAN.md.
5. `pnpm validate` passes schema and data integrity checks.
6. `pnpm build:data` executes `build-municipalities.ts` and prints national and sample prefecture summaries for verification.

## 3. Detailed Step-by-Step Plan

### Step 1: Implement `scripts/build-municipalities.ts` and Data Generation
- Source data: Construct a clean, authoritative generator incorporating the official 47 prefectures and 1,741 municipal assemblies (with 5-digit `code5`, 6-digit `code6`, `pref_code`, `pref_name`, `name`, `kind`, `parent_code5`, `population`, `population_ref_date`).
- Exclude the 6 northern territory villages (which lack functioning assemblies) to match the exact 1,741 denominator.
- Ensure all 20 designated cities (政令指定都市) are properly represented with their parent codes, and administrative wards are mapped to their parent city `code5`.
- Add `"build:data": "tsx scripts/build-municipalities.ts"` to `package.json`.
- Run `pnpm build:data` to generate `data/municipalities.csv`.

### Step 2: Implement Complete Metrics Engine in `src/lib/metrics.ts`
- Implement `calculateNationalMetrics(sites: SiteEntry[], municipalities: Municipality[]): NationalMetrics`.
- Implement `calculatePrefectureMetrics(sites: SiteEntry[], municipalities: Municipality[]): PrefectureMetrics[]`.
  - Group municipalities by prefecture (`pref_code`).
  - Calculate municipal coverage (count of covered municipalities ÷ count of municipalities in that prefecture).
  - Calculate population coverage (covered municipal population ÷ total municipal population in that prefecture).
  - Check whether a prefectural assembly site (`assembly_level === 'prefectural'`) is active/stale.
  - Sort prefectures: `populationCoverageRate` desc, then `municipalCoverageRate` desc, then `prefCode` asc.
  - Assign 1-indexed `rank` to each prefecture.
- Export utility helper functions: `formatPercent`, `formatPopulation`.

### Step 3: Expand Unit Tests in `tests/metrics.test.ts`
- Test full national aggregation with mock municipalities and mock sites.
- Test prefecture ranking and tie-breaking order.
- Test edge cases:

  3. Status behavior: `stale` counts; `dead` and `building` do not count.
  4. Zero coverage prefecture has coverage 0, proper denominator, rank at the bottom.

## Changes from Plan

1. **Data sources (Step 1).** The generator reads 総務省 files from `data/raw/` (`code_list.xlsx`, R6.1.1 edition, the latest published code list; `population.xlsx`, 令和8年1月1日 住基人口 総計) instead of embedding data. URLs are in `data/raw/README.md`. Approved by the user. Total population (123,767,642) matches the source's 合計 row.
2. **New dependencies.** `exceljs` (read .xlsx in the generator) and `@vitest/coverage-v8` (to measure the "100% coverage" criterion; metrics.ts reports 100% statements/branches/functions/lines).
3. **Designated-city wards.** Followed PLAN.md §5, not plan Step 1: ward rows are not in the CSV, and `parent_code5` is left empty for all rows. The ward-to-city lookup stays in the Phase 2 geo build. Approved by the user.
4. **北方領土 exclusion.** Matched via the county-qualified names in the population table (e.g. 国後郡泊村), because the plain name 泊村 also belongs to a real Hokkaido village.
5. **New file `src/lib/data.ts`.** snake_case to camelCase loaders for the CSV and YAML, shared by the `build:data` summary and tests. It contains no coverage math; the summary numbers come from `metrics.ts`.
6. **`sites.yaml` seeded with 4 of 11 entries** (Shinjuku, Setagaya, Fukuoka Pref, Akitakata). Only entries whose site URL and repo I could verify (repo `homepage` via `gh api` plus an HTTP 200) were added. Unverified `operator` and `launched_on` values are omitted pending manual confirmation. Not seeded, needing a human decision:
   - Ota: homepage points to the national site; real URL unknown; status "active / stale" is ambiguous.
   - Kawasaki: site returns 200 but repo `GondoTakashi/mirai-gikai-kawasaki` returns 404, and no repo URL is known.
   - Fukuoka City: homepage points to the Kawasaki site.
   - Numazu: homepage points to the national site.
   - Tagawa: no homepage.
   - Sapporo: homepage `project-5ki8w.vercel.app` returns 404.
   - Onga: not public yet (`building`); no URL, and the schema requires https.
7. **`validate.ts`.** Now validates every municipality column, code relationships and check digits, allowed kinds, the reference date, population safety, uniqueness, prefecture membership, parent references, and exact category totals. It also requires prefectural sites to use real prefecture rows and rejects municipal sites pointing at prefecture codes. The Date-or-string handling for site data already existed.
8. **`.gitignore`** gains `coverage/`.
9. **Existing Shinjuku entry corrected.** The unverified Phase 0 placeholder values for `operator` and `launched_on` were removed pending manual confirmation. Fukuoka Pref's `name` now matches the live site's title (みらい議会＠福岡県).
10. **Generator guard.** `build:data` also fails unless the population workbook's title row contains 令和8年1月1日.
11. **Optional unverified metadata.** `operator` and `launched_on` are optional until a human verifies them. Registry notes identify entries that still need confirmation.
